# 使用与标定指南

## 前置条件

| 项目 | 要求 | 检查方式 |
|---|---|---|
| LSPosed | v1.9+，已启用 | 模块列表里能看到「领克无感钥匙」 |
| 作用域 | `com.lynkco.customer` | 已由 `xposedscope` 自动配置 |
| 官方 APP | 已登录，蓝牙钥匙可用（能手动解锁） | 官方 APP → 爱车 → 手机钥匙 |
| 蓝牙 | 打开 | — |

模块装好后**必须重启官方 APP**（或重启手机）才会注入。

## 一、先在室内验证链路（不需要车）

打开自研 APP「领克无感钥匙」，点 **STATUS**，应看到类似：

```
STATUS dkId=5635***9480 BleEventHandler.connectStatus=false
```

- `dkId` 非空 → 桥接通，已拿到候选钥匙标识
- `connectStatus=false` → 正常（车不在旁边）

再点 **ENUMS**，应返回 30 个 `BleControlType` 与 4 个 `CmdChannel`。
**这两步通过，说明反射链路完全打通**，剩下只是现场调参。

若 `STATUS` 返回 `ERR 超时`：官方 APP 进程没起或者模块没注入，先把官方 APP 打开一次。

## 二、到车边验证（关键）

### 步骤 1：让官方 APP 先连一次

进官方 APP → 爱车 → 点「连接车辆」，确认「手机钥匙」显示已连接。

这一步有两个作用：
- 验证蓝牙钥匙本身正常
- **让模块学到真实 dkId**（日志会出现 `LEARN dkId=xxx`）

### 步骤 2：测试命令通道

在自研 APP 里点 **UNLOCK**。

可能的结果：

| 返回 | 含义 | 下一步 |
|---|---|---|
| `OK 已提交(挂起)` | 命令已进入官方协程 | 看车是否解锁 |
| `OK 返回xxx` | 同步返回 | 看车是否解锁 |
| `OK 异常:...` | 反射调用抛错 | 把日志发我 |
| `ERR 超时` | 官方 APP 进程不在了 | 打开官方 APP 再试 |

### 步骤 3：看 RSSI

点「扫描周围 BLE 设备」，确认列表里出现 `AA:BB:CC:DD:EE:FF`。

**如果扫不到这个 MAC**，说明车机不做持续广播，或者地址是随机化的 ——
这时 RSSI 测距方案不成立，需要改用其他触发源（把扫描结果发我）。

### 步骤 4：标定阈值

**当前出厂参数：解锁 -75 dBm / 上锁 -82 dBm / 驻留 4.5 s**（已内置，车边不用重填）。

站到离车 2~3 米处，看 APP 上的「RSSI 原始/平滑」读数，记下来。
然后走到 15 米外再看一次。

主界面 MAC 输入框下面有三个输入框（**依次：解锁 dBm / 上锁 dBm / 驻留 s**），
改完点「应用」会立即下发给模块，不用重启：

- **解锁 dBm**：略低于"2~3 米"处的平滑值（比如测到 -70，就填 -75）
- **上锁 dBm**：略高于"走远"处的平滑值（比如测到 -88，就填 -82）
- 两者至少差 5 dB，否则会在边界来回抖动（当前 -75/-82 相差 7 dB）
- **驻留 s**：连续满足条件持续多久才动作，当前 4.5 秒

驻留按**真实时间**计，不按广播包个数计 —— 车机广播频率变化不会改变手感。

命令行等价写法：

```
CONFIG <解锁dBm>,<上锁dBm>,<解锁驻留ms>,<上锁驻留ms>
例：CONFIG -75,-82,4500,4500
```

## 三、日常使用

1. 自研 APP 点「启动无感」，出现常驻通知
2. 官方 APP 无需打开（但进程不能被杀）
3. 小米设置里给**两个 APP** 都做以下设置：
   - 省电策略 → 无限制
   - 允许自启动
   - 最近任务里下拉锁定
   - 后台弹出界面 → 允许

官方 APP 的保活尤其重要：**它活着，感知层才活着**。

## 四、排障

### 看不到任何效果

按顺序查：

```bash
# 1. 模块是否注入（应看到"模块已注入"与"BridgeReceiver 已注册"）
adb logcat -d | grep "PassiveKey"

# 2. 感知是否在跑（running=true，hits 会随时间增长）
adb logcat -d | grep "感知已启动"

# 3. 官方 APP 进程是否活着
adb shell ps -A | grep lynkco
```

### `hits=0` 一直不动

扫不到车机。原因通常是：
- 车机 BLE 未广播（需要先被唤醒，比如拉一下门把手）
- MAC 变了（RPA 随机地址）
- 距离太远

### 能扫到但不动解锁

查 `dkId` 是否正确：

```bash
adb shell su -c "grep -E 'LEARN|FIRE|SEND' /data/data/com.lynkco.customer/files/pk_recon.txt | tail -20"
```

若出现 `LEARN dkId=` 且与 `dk_userid` 不同，说明自动学习生效，
`DkBridge` 会优先用它。

### 明明在车旁却判定为离开

`lostTimeoutMs`（45 秒无广播即判离开）太短，或车机广播间隔不稳定。
把驻留时间调大、上锁 dBm 调低。

### 人在车旁走动就被锁了

上车前绕到车尾拿东西、RSSI 掉到 -82 以下并持续 4.5 秒就会触发上锁。
把驻留从 4.5 调到 6~8 秒，或把上锁 dBm 降到 -86。

## 五、日志位置

模块把全过程写在官方 APP 的私有目录：

```
/data/data/com.lynkco.customer/files/pk_recon.txt
```

关键行：

| 行 | 含义 |
|---|---|
| `WATCHER_START mac=` | 感知启动成功 |
| `LEARN dkId=` | 学到真实 dkId |
| `APPROACH rssi=` | 判定靠近 |
| `DEPART rssi=` | 判定离开 |
| `FIRE DOOR_UNLOCK => ...` | 实际下发解锁及结果 |
| `SEND ... -> ...` | 反射调用明细 |
| `FLOW_SUBSCRIBED ...` | 冷流已被订阅，命令真正开始执行（**没有这行等于没发**） |
| `DIAG_TARGET_HIT ...` | 无过滤扫描命中了目标 MAC |
| `CMD xxx` | 收到主 APP 的指令 |

## 六、第一轮车边实测：无法解锁（2026-11-10 20:20）

### 根因 1：命令是冷流，从未真正发出（已修复）

当时手动点 `UNLOCK` 两次，模块日志是：

```
SEND DOOR_UNLOCK via DK20 -> ChannelFlowBuilder[capacity=-2]
```

`NearbyControlSend.sendControlCmd` 是 `channelFlow { ... }` 构造的 suspend 函数，
直接反射调用只拿到一个**冷流对象**，内部真正发帧的 `handleControlCommand`
要等 Flow 被订阅才执行。原实现拿到对象就返回 `已提交`，所以车端什么都没收到。

现在 `DkBridge.subscribeFlow()` 会反射 `FlowKt.launchIn(flow, scope)`，
用官方 APP 自己的 `BleEventHandler.scope`（Dispatchers.IO）订阅，修复后日志：

```
FLOW_SUBSCRIBED DOOR_UNLOCK/DK20 via kotlinx.coroutines.flow.FlowKt
  scope=BleEventHandler.scope job=StandaloneCoroutine{Active}
```

### 根因 2 & 3：待车边确认

| 现象 | 当时读数 | 说明 |
|---|---|---|
| 蓝牙钥匙未连接 | `connectStatus=false` | 命令无处可发，必须先让官方 APP 连上 |
| 感知未命中 | `hits=0`、`smooth=0` | 带 MAC 过滤的扫描从没扫到车机 |

注意 `hits=0` 时调阈值、缩驻留都没有意义 —— 判定环节根本没进入。
当时把参数调到 `-67,-73,500,500` 就是这个误区。

### 第二轮车边复测顺序（务必按序）

1. **先让官方 APP 连上蓝牙钥匙**：领克 APP → 爱车 → 「连接车辆」，
   确认「手机钥匙」显示**已连接**。这一步不能省 —— 我们的模块只是
   在官方 APP 进程里代按按钮，连接仍由官方 APP 建立。
2. 点我们 APP 的 **STATUS**，确认 `connectStatus=true`。
3. 点 **UNLOCK**，看车有没有反应，并把 `pk_recon.txt` 里
   `FLOW_SUBSCRIBED` 之后的内容发我。
4. 点 **SCAN**（无过滤扫描 10 秒）→ 等 10 秒 → 点 **RESULT**。
   这一份列表能回答「车机到底广播什么 MAC」：
   - 列表里有 `AA:BB:CC:DD:EE:FF` → MAC 没错，是阈值/驻留标定问题
   - 列表里没有，但有个信号很强的不知名设备 → 车机用了随机地址，
     把那个地址填进 MAC 输入框，再点「应用」
   - 目标命中 0 次且附近只有智能家居设备 → **车机不持续广播**，
     RSSI 测距方案不成立，需要换触发源（这个结论很重要）

> `SCAN` 是短时诊断，只在排查时点；常驻感知仍走 MAC 过滤扫描，
> 否则息屏后会被系统限流。

## 七、回滚

不想要了，把模块禁用即可，官方 APP 不受任何影响 ——
本方案没有修改官方 APP 的任何文件、dex 或签名。

```bash
adb shell am force-stop com.lynkco.customer
```

然后在 LSPosed 里关掉「领克无感钥匙」的开关。
